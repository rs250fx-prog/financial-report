## 2. 絶対に守ること

実際に事故になったもの、および媒体の前提として外せないもの。

- **数値を創作しない。**確認できない指標は「未確認」と書く。検査は形式しか見ないので、
  もっともらしい誤った数字は検査も人のざっと見も通り抜ける
- **要約から数値を読まない。**Web取得ツールは数値を作る（後述 §3）。生ファイルの行を見る
- **個別の売買推奨を書かない。**投資助言・代理業の登録が無い。情報提供と分析にとどめる
- **`git add -A` を使わない。**ユーザーが並行編集する。変更したファイルを明示して add する
- **定期実行は `draft: true` のまま push する。**公開は人が `/admin` から行う
- 構造・運用ルールを変えたら、**同じコミットで `docs/SPEC.md` の更新履歴も更新する**

## 3. このセッションでやったこと

### 指標の取得元を確定した（`960749a`）

実質金利（TIPS10年）が9本中7本で「未確認」のまま残っていた。**原因は探し方だった。**
報道記事はこの指標を「今日の値」として書かないので、ニュース検索では出てこない。
FRED に毎営業日の確定値があり、鍵もアカウントも要らない。

- `tools/fetch-indicators.py` で7指標を一括取得
- `docs/SOURCES.md` に取得元を定義、公開ページ `/sources/` で開示
- **系列ごとに1〜2営業日の遅れがある。**「9/29時点」と添えて載せ、翌号で差し替える。
  **遅れを理由に空欄にしない**

### シナリオの答え合わせを始めた（`960749a` / `fbff0c8`）

毎号シナリオを出しながら、どうなったかを検証していなかった。方針と矛盾する。

- 日次 frontmatter に `review`（`of` / `verdict` / `scenario` / `note`）
- 判定は4値。**二択にすると「方向は合ったが経路が違った」が hit に寄る**
- 履歴は `/review/`、ナビに「答え合わせ」
- **過去号には遡らない。**結果を知ったあとに書く検証は検証にならない。
  境界は `tools/check-report.py` の `REVIEW_SINCE = "2026-09-30"`

### 取得の失敗と、要約による数値の捏造（`1b6a794`）★重要

10/1の定期実行で実質金利がまた未確認になった。報告は
「FREDへの接続が**環境の制約で失敗**」。**プロンプトは正しく動いていた**（`review` も
正しく入っていた）。クラウドのサンドボックスが Python からの外向き通信を塞いでいる。

代替としてWeb取得ツールを使わせる前に検証したところ、**このツールは数値を作ることが分かった。**

| 実測 | 結果 |
|---|---|
| FREDのCSVを読ませる | **存在しない土曜日（2026-09-26）の行**が混ざった |
| curlで空を返すURLを読ませる | もっともらしい数値を**5行生成**した |
| 同じ取得の中で | 正しい値（9/29, 2.91）と架空の行が**並んでいた** |

ページを小さなモデルに通して要約する構造のため、読めなかった箇所を埋めようとする。
**生ファイルは正しく保存されている**ので、要約ではなくそれを開いて `YYYY-MM-DD,値` の
行を読む手順にした。日付が平日か・直近かという形式の検証も課している。
（今回の事故は「土曜の行がある」ことで気づけた）

### 10/1号を確定値に差し替えた（`3766b57`）

公開から時間が浅いうちに正した。値を入れるだけでは本文と矛盾するため、**分析も書き直した。**

## 4. 次にやること（優先度順）

### 4-0. クラウド環境の外向き通信を開ける ★未解決・最優先

**10/2 の定期実行は記事を書けずに終わった。**クラウド環境の Network access が既定の Trusted のままで、
FRED・報道サイト・CoinGecko・財務省のどれにも届かなかった（CONNECT が 403）。Web取得ツールも
EGRESS_BLOCKED になり、使えたのは検索の要約だけだった。**要約からは数値を読まない規則なので、
書かずに終えたのは正しい動作である。**10/2号はローカルのセッションで作成した。

直し方（管理画面側の操作。AIからは変えられない）：

- ルーティンの編集画面の雲のアイコンから、**そのルーティンが使っている環境**を開く
- Network access を **Full** にする。Custom でドメインを列挙する場合の一覧は下記
- ドキュメント上、変更は実行中のセッションにも約1分で反映される。10/2 に「許可したのに
  反映されなかった」のは、**ルーティンとは別の環境を編集した可能性が高い**（未確認）

10/2号で実際に使ったホスト：


報道ソースは日によって変わるので、列挙では毎日どこかが欠ける。**Full が現実的。**
このルーティンにはリポジトリへの書き込み以外の権限もコネクタも付けていない。

**開くまでは、ローカルのセッションで手順どおりに作れば通る。**`should-run.py` は
引数なしだと UTC の日付で判定するので、`--date YYYY-MM-DD` を付けること。

**「前後」「小動き」は後から数値として読めない。**ここも併せて整理する。

これは §5 の時系列ページの前提条件でもある。

**規則と検査はまだ足していない。**10/1号は `ドル指数 DXY` と `BTC / USD` がレンジ表記のまま残っている。
