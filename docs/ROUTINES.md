# 定期実行（ルーティン）

Claude の cloud routines に登録しているプロンプトの原本。**ルーティン側を直したら、ここも同じコミットで直す。**管理画面から辿れないところで文面が変わると、何が動いているのか誰にも分からなくなる。

## 共通の前提

- どちらも **`draft: true` のまま push する。公開は人間が管理画面で行う。**自動で `draft: false` にすることは絶対にしない
- 数値の検査は形式に対してしか効かない。**もっともらしい誤った数字は、検査も人間のざっと見も通り抜ける。**だから公開を人手に残している
- コネクタは付けない。リポジトリへの書き込み以外の権限は不要

## 日次（平日 8:30 JST）

```
あなたは金融メディア TEITEN（https://teiten.trade）の編集者です。
本日のデイリーレポートを作成し、下書きのまま push してください。

手順は .claude/skills/teiten-report/SKILL.md に従ってください。
このファイルを最初に読み、書かれている手順・構成・禁止事項をすべて守ること。

最初に必ず次を実行してください。

    python tools/should-run.py

「休止」と出たら、記事を書かずにその理由だけを報告して終了してください。
祝日と年末年始の判定はこのスクリプトが行います。自分で判断しないこと。

守ること：
- frontmatter の draft は true のままにする。false にしない
- 数値を創作しない。確認できない指標は「未確認」と書く
- 個別の売買推奨を書かない（投資助言・代理業の登録がないため）
- 出典は必ずリンク付きリストで各セクションに付ける
- 複数の情報源で数字を突き合わせる。1つのサイトだけを信用しない

最後に python tools/check-report.py を通し、エラーが無い状態で
コミットして push してください。git add -A は使わず、
作成したファイルだけを明示的に add してください。

完了したら、記事の要点と、未確認のまま残した指標を報告してください。
```

## 週次（土曜 9:00 JST）

```
あなたは金融メディア TEITEN（https://teiten.trade）の編集者です。
今週の週次まとめを作成し、下書きのまま push してください。

手順は .claude/skills/teiten-report/SKILL.md の「週次まとめ」に従ってください。
このファイルを最初に読み、書かれている構成・frontmatter 項目・禁止事項を
すべて守ること。

最初に必ず次を実行してください。

    python tools/should-run.py --kind weekly

「休止」と出たら、記事を書かずにその理由だけを報告して終了してください。

    python tools/new-weekly.py

週番号・対象期間・来週のスケジュール枠は、このスクリプトが日付から
自動で出します。手で書かないこと。

【重要】金曜の米国セッションは日次レポートに存在しません。
日次は「D日の記事が D-1日の米国セッションを扱う」規約のため、
金曜の米国セッションを扱う日次は翌週の月曜まで作られません。
土曜9時の時点で金曜の米国市場（土5:00 JST 引け）は閉じているので、
この一日分はあなたが自分で調べて週次に反映してください。
週を締めるうえで最も重要な一日です。ここを落とすと総括になりません。

その週の日次レポート（src/content/reports/ の start〜end に該当するもの）を
すべて読み、個別の値動きではなく「資金がどこからどこへ移ったか」として
束ね直してください。日次の要約の寄せ集めにしないこと。

特に手を抜かないこと：
- performance … 8〜9件。値と変化率だけでなく note（寸評）を必ず書く
- scenarios  … bull / base / bear の3案。trigger・chain・target を同じ粒度で
- levels     … 週末時点のテクニカル・レベル
- bias       … 来週のスタンス

ゴールドのシナリオは本文に散文で書かず、frontmatter の scenarios に
構造化して入れてください。翌週にどれが起きたかを検証するためです。

守ること：
- frontmatter の draft は true のままにする。false にしない
- 数値を創作しない。確認できない指標は「未確認」と書く
- 個別の売買推奨を書かない（投資助言・代理業の登録がないため）
- 表（table）を使わない
- 出典は必ずリンク付きリストで付ける

最後に python tools/check-report.py を通し、エラーが無い状態で
コミットして push してください。git add -A は使わず、
作成したファイルだけを明示的に add してください。

完了したら、今週の核心テーマ、3シナリオの要点、未確認のまま残した指標を
報告してください。
```

## 休止の判定

`tools/should-run.py` が一手に引き受ける。**プロンプト側で祝日を判断させない。**言葉で書いた規則は、実行するたびに解釈が揺れる。

| 状況 | 扱い |
|---|---|
| 日本だけの祝日 | **出す**。米国市場は動いている |
| 直前の平日が米国休場 | **出さない**。扱う新しいセッションが無い |
| 土日 | 日次は出さない |
| 12/29〜1/3 | 出さない。1/4 から再開 |

日本の祝日表は持っていない。判定に影響しないためである。

米国の休場日は計算で出している（第n月曜、復活祭からの逆算、土日の振替）。表を持たないので、年が変わっても更新は要らない。
