# 定期実行（ルーティン）

Claude の cloud routines に登録しているプロンプトの原本。**ルーティン側を直したら、ここも同じコミットで直す。**管理画面から辿れないところで文面が変わると、何が動いているのか誰にも分からなくなる。

## 共通の前提

- どちらも **`draft: true` のまま push する。公開は人間が管理画面で行う。**自動で `draft: false` にすることは絶対にしない
- 数値の検査は形式に対してしか効かない。**もっともらしい誤った数字は、検査も人間のざっと見も通り抜ける。**だから公開を人手に残している
- コネクタは付けない。リポジトリへの書き込み以外の権限は不要
- モデルは Fable 5.1
- **クラウド環境は「Full」（Network access: Full）を選ぶ。**既定の「Default」は Trusted で、FRED・報道サイト・財務省・CoinGecko に届かない。10/2 の日次はこれで書けずに終わった。環境変数とセットアップスクリプトは空でよい（`npm ci` は手順の中で実行する）

## 日次（平日 8:00 JST 開始。公開は 8:15 前後）

```text
金融メディア TEITEN（定点）のデイリーレポートを作成し、公開の条件を満たせば公開状態で、満たさなければ下書きのまま push してください。あなたはこのリポジトリのクローンを持つクラウド環境で動いています。

## まず読むもの

着手前に必ず次の2つを読み、書式・判断基準・禁止事項をすべて把握してください。

- `.claude/skills/teiten-report/SKILL.md` … 作成手順、frontmatter の規則、本文の12節構成、やってはいけないこと
- `docs/SPEC.md` … サイトの構造、コンテンツモデル、設定の集約先

既存の `src/content/reports/*.md` を1本読み、文体と密度を合わせてください。

## 対象日

日本時間（JST）での本日の日付を対象にします。`TZ=Asia/Tokyo date +%F` で確認してください。

扱う市場は、原則として前営業日の米国セッションです。JST の朝時点で確定しているのはそこまでのためです。前号と同じ値動きを二重に書かないでください。

## 出す日かどうかの確認

着手する前に必ず次を実行してください。

    python tools/should-run.py

「休止」と出たら、記事を書かずにその理由だけを報告して終了してください。終了コードは 10 です。

祝日と年末年始の判定はこのスクリプトが行います。自分で判断しないでください。

## push できるかを先に確かめる

**記事を書き始める前に**次を実行してください。

    git push --dry-run origin main

`403` や `Resource not accessible by integration` で失敗したら、**記事を書かずに**
「push 権限が無い」ことだけを報告して終了してください。

調べて書いてから push に失敗すると、原稿ごと失われます。クラウド実行環境は
実行が終わると破棄されるため、**ローカルに残したコミットは取り出せません。**

## 手順

1. `python tools/new-report.py <YYYY-MM-DD>` で雛形を作る。号数は自動採番されるので手で付けない
2. `python tools/fetch-indicators.py` を実行する。実質金利・VIX・米金利はここで取る。
   **出力の「◯/◯時点」を落とさずに本文へ書くこと。**残りをウェブ検索で補う。
   SKILL.md の「データを集める」節に挙がっている項目をすべて当たる。

   **このスクリプトから通信できない場合がある**（実行環境が外向き通信を塞ぐため。
   実際に起きた）。その場合スクリプトが代替手順とURLを出すので、必ずそれに従う。
   **ここで諦めて「未確認」にしない。**

   代替手順で取るときの絶対条件：**要約された文章から数字を読まない。**
   保存された生ファイルを開き `YYYY-MM-DD,値` の行をそのまま読む。
   要約を通すと数値が作られる（存在しない土曜日の行が混ざった実例がある）。
2-B. 前号の Next Flow を読み、どのシナリオが起きたかを frontmatter の `review` に記録する
   （SKILL.md の「前号の答え合わせを書く」節）。**外れた回も同じ形式で残す**
3. データを検証する。複数ソースで突き合わせ、矛盾したら日付と具体性のあるほうを採る。矛盾したまま採用しない。唯一の出所しかない指標は掲載せず「未確認」と書く
4. 本文を書く。12節すべてを埋める。節を省略しない
5. `python tools/check-report.py <YYYY-MM-DD>` を実行し、エラーが0になるまで直す
5-B. 公開してよいかを判定する（下の「公開の判定」節）。公開する場合だけ
   `python tools/publish-gate.py <YYYY-MM-DD> --apply` を実行する。**`draft:` の行を手で書き換えない**
6. `npm ci && npm run build` でビルドが通ることを確認する。**公開状態（draft: false）にした号でビルドが失敗したら、
   `python tools/publish-gate.py <YYYY-MM-DD> --hold` で下書きに戻す。**下書きのままの号は、npm が失敗しても
   検査が通っていれば次へ進み、その旨を結果に書く
7. note 用の簡易版を `note/<YYYY-MM-DD>.md` に書く（SKILL.md のステップ8）
7-B. frontmatter の `thumb` に大タイトル・中タイトル・小見出し・数値5枠の寸評を書き、
   `node tools/make-thumb.mjs <YYYY-MM-DD>` で note 用サムネイルを書き出す（SKILL.md のステップ8-B）。
   **エラーが出たら文言を短くして、通るまでやり直す。**`thumb` に数値の欄は無い（snapshot から取る）。
   手順6で npm が失敗していて書き出せない場合は、`thumb` の文言だけ書いて次へ進み、その旨を結果に書く
8. commit して `main` に push する。`note/thumb_<YYYYMMDD>.png` も add に含める

## 公開の判定

この号は、人の確認を待たずに朝の定時に公開します。問題があれば人があとから非公開に戻します。
**ただし、大きな問題がありそうな号は公開せず、下書きのまま push して人の確認に回してください。**

次のどれかに当てはまる号は「大きな問題がありそう」と扱い、`--apply` を実行しません。

- 金・ドル指数・米10年債・WTI・主要な株価指数のいずれかで、出所の値が食い違ったまま決着できなかった
- 上の主要な数値を、一次データ（FRED・財務省・取引所など）でも複数の報道でも確かめられず、
  1件の要約や検索結果の抜粋だけに頼った
- 公開済みの過去の号に数値の誤りを見つけた（訂正の判断が要るため）
- 手順のどこかが失敗したまま残っている（`fetch-indicators.py` も代替手順も通らなかった、など）
- 書き終えた内容に自信が持てない点が残っている

当てはまらなければ `python tools/publish-gate.py <YYYY-MM-DD> --apply` を実行します。このスクリプトも
機械で分かる条件（検査のエラー、主要指標の未確認、snapshot の欠け、発行日のずれ、`review` の欠落）を
確かめ、通らなければ「保留」と理由を出して終了コード 1 を返します。**「保留」が出たら公開しません。**
理由を直せるなら直して再実行し、直せなければ下書きのまま進めます。

迷ったら公開しないでください。下書きで出した号は人が数分で公開できますが、
誤った数字を公開すると読者の判断を誤らせます。

## 絶対に守ること

- `draft:` の行を手で書き換えないでください。公開は `tools/publish-gate.py --apply` だけで行います。雛形は draft: true で生成されます
- 数値を創作しないでください。出典が確認できない値は載せない。取れなかった指標は「未確認」と明記する
- 個別の売買推奨を書かないでください。投資助言・代理業の登録がないため、情報提供と分析にとどめます
- `git add -A` を使わないでください。作成したファイルを明示して add します（ユーザーが同じリポジトリを並行して触ることがあるため）
- コミットメッセージは日本語で、何を書いたかが分かる内容にしてください。公開状態で出した号は「公開」、下書きで出した号は「下書き」と書く

## 完了時の報告

次を簡潔に報告してください。

- **公開したか、下書きで止めたか。**止めた場合はその理由（`publish-gate.py` の出力、または上の判定のどれに当たったか）
- 作成したファイルのパスと号数
- 検査の結果（エラー・警告の件数）
- その日の中心的な論点を2つ
- 取得できなかった指標があれば、その一覧
- note 用サムネイル（`note/thumb_<YYYYMMDD>.png`）を書き出せたか。「注意」が出た行があればその内容。
  画像のURL（`https://teiten.trade/thumb/<YYYY-MM-DD>.png`。push の1〜2分後から開ける）
- push したコミットのハッシュ

**push に失敗した場合は、作成した記事の全文（frontmatter を含む）を報告に
そのまま貼り付けてください。**実行環境は破棄されるため、報告に載せなかった
ものは失われます。
```

## 休止の判定

`tools/should-run.py` が一手に引き受ける。**プロンプト側で祝日を判断させない。**言葉で書いた規則は、実行するたびに解釈が揺れる。

| 状況 | 扱い |
|---|---|
| 日本だけの祝日 | **出す**。米国市場は動いている |
| 直前の平日が米国休場 | **出さない**。扱う新しいセッションが無い |
| 土日 | 日次は出さない |
| 12/29〜1/3 | 出さない。1/4 から再開 |

「直前の平日が米国休場なら出さない」のは、単に前日が休みだからではない。**その日の号が既に最新のセッションを扱っているためである。**金曜がグッドフライデーなら、金曜の号が木曜分を扱っており、月曜に書くことは何もない。「前営業日が休場か」で判定すると、この月曜を取りこぼす。

日本の祝日表は持っていない。判定に影響しないためである。

米国の休場日は計算で出している（第n月曜、復活祭からの逆算、土日の振替）。表を持たないので、年が変わっても更新は要らない。
