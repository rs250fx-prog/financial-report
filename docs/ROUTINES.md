# 定期実行（ルーティン）

Claude の cloud routines に登録しているプロンプトの原本。**ルーティン側を直したら、ここも同じコミットで直す。**管理画面から辿れないところで文面が変わると、何が動いているのか誰にも分からなくなる。

## 共通の前提

- どちらも **`draft: true` のまま push する。公開は人間が管理画面で行う。**自動で `draft: false` にすることは絶対にしない
- 数値の検査は形式に対してしか効かない。**もっともらしい誤った数字は、検査も人間のざっと見も通り抜ける。**だから公開を人手に残している
- コネクタは付けない。リポジトリへの書き込み以外の権限は不要
- モデルは Opus 5

## 日次（平日 8:30 JST）

```text
金融メディア TEITEN（定点）のデイリーレポートを、下書きとして作成し push してください。あなたはこのリポジトリのクローンを持つクラウド環境で動いています。

## まず読むもの

着手前に必ず次の2つを読み、書式・判断基準・禁止事項をすべて把握してください。

- `.claude/skills/teiten-report/SKILL.md` … 作成手順、frontmatter の規則、本文の12節構成、やってはいけないこと
- `docs/SPEC.md` … サイトの構造、コンテンツモデル、設定の集約先

既存の `src/content/reports/*.md` を1本読み、文体と密度を合わせてください。

## 対象日

日本時間（JST）での本日の日付を対象にします。`TZ=Asia/Tokyo date +%F` で確認してください。

扱う市場は、原則として前営業日の米国セッションです。JST の朝時点で確定しているのはそこまでのためです。前号と同じ値動きを二重に書かないでください。

## 出す日かどうかの確認

着手する前に必ず次を実行してください。

    python tools/should-run.py

「休止」と出たら、記事を書かずにその理由だけを報告して終了してください。終了コードは 10 です。

祝日と年末年始の判定はこのスクリプトが行います。自分で判断しないでください。

## push できるかを先に確かめる

**記事を書き始める前に**次を実行してください。

    git push --dry-run origin main

`403` や `Resource not accessible by integration` で失敗したら、**記事を書かずに**
「push 権限が無い」ことだけを報告して終了してください。

調べて書いてから push に失敗すると、原稿ごと失われます。クラウド実行環境は
実行が終わると破棄されるため、**ローカルに残したコミットは取り出せません。**

## 手順

1. `python tools/new-report.py <YYYY-MM-DD>` で雛形を作る。号数は自動採番されるので手で付けない
2. ウェブ検索でデータを集める。SKILL.md の「データを集める」節に挙がっている項目をすべて当たる
3. データを検証する。複数ソースで突き合わせ、矛盾したら日付と具体性のあるほうを採る。矛盾したまま採用しない。唯一の出所しかない指標は掲載せず「未確認」と書く
4. 本文を書く。12節すべてを埋める。節を省略しない
5. `python tools/check-report.py <YYYY-MM-DD>` を実行し、エラーが0になるまで直す
6. `npm ci && npm run build` でビルドが通ることを確認する（npm が失敗しても、検査が通っていれば次へ進み、その旨を結果に書く）
7. note 用の簡易版を `note/<YYYY-MM-DD>.md` に書く（SKILL.md のステップ8）
8. commit して `main` に push する

## 絶対に守ること

- `draft: true` のままにしてください。`draft: false` にしないこと。人間が管理画面で内容を確認してから公開します。雛形は draft: true で生成されるので、そのまま触らないでください
- 数値を創作しないでください。出典が確認できない値は載せない。取れなかった指標は「未確認」と明記する
- 個別の売買推奨を書かないでください。投資助言・代理業の登録がないため、情報提供と分析にとどめます
- `git add -A` を使わないでください。作成したファイルを明示して add します（ユーザーが同じリポジトリを並行して触ることがあるため）
- コミットメッセージは日本語で、何を書いたかが分かる内容にしてください

## 完了時の報告

次を簡潔に報告してください。

- 作成したファイルのパスと号数
- 検査の結果（エラー・警告の件数）
- その日の中心的な論点を2つ
- 取得できなかった指標があれば、その一覧
- push したコミットのハッシュ

**push に失敗した場合は、作成した記事の全文（frontmatter を含む）を報告に
そのまま貼り付けてください。**実行環境は破棄されるため、報告に載せなかった
ものは失われます。
```

## 休止の判定

`tools/should-run.py` が一手に引き受ける。**プロンプト側で祝日を判断させない。**言葉で書いた規則は、実行するたびに解釈が揺れる。

| 状況 | 扱い |
|---|---|
| 日本だけの祝日 | **出す**。米国市場は動いている |
| 直前の平日が米国休場 | **出さない**。扱う新しいセッションが無い |
| 土日 | 日次は出さない |
| 12/29〜1/3 | 出さない。1/4 から再開 |

「直前の平日が米国休場なら出さない」のは、単に前日が休みだからではない。**その日の号が既に最新のセッションを扱っているためである。**金曜がグッドフライデーなら、金曜の号が木曜分を扱っており、月曜に書くことは何もない。「前営業日が休場か」で判定すると、この月曜を取りこぼす。

日本の祝日表は持っていない。判定に影響しないためである。

米国の休場日は計算で出している（第n月曜、復活祭からの逆算、土日の振替）。表を持たないので、年が変わっても更新は要らない。
